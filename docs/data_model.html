Rules and constraints

Enforced by the database

  • Primary keys are UUID strings; foreign keys are enforced.
  • Deleting a folder cascades to child folders, quizzes, questions, options and attempts.
  • Deleting a quiz cascades to its questions, options and attempts.
  • question.type is one of mcq, msq, numerical.
  • marks > 0; tolerance IS NULL OR tolerance >= 0.
  • Booleans are stored as INTEGER 0/1.

Enforced by the domain layer

  • Folder names are trimmed, 1–60 chars, and unique among siblings (case-insensitive). SQLite cannot do this reliably for root-level NULL parents.
  • MCQ has exactly one correct option; MSQ has at least one.
  • ended_at >= started_at; duration_ms is derived from both timestamps.
  • score and max_score are computed when the attempt ends.
  • Numerical questions require an answer; non-numerical questions must not store one.
  • An attempt stores max_score at the time it ran, so future mark changes cannot rewrite history.

Import mapping

  • MCQ → mcq, MSQ → msq, NAT → numerical.
  • Quiz subtitle → quiz.subtitle; key → quiz.source_key (not unique).
  • d → question.difficulty (lower-cased); e → explanation; u → unit.
  • 0-based option indices become rows with is_correct = 1.
  • Every question has marks = 1 because the source format has no marks field.
  • Unknown fields are ignored; the original JSON is not stored.

Attempt answers JSON

attempt.answers_json keeps the user's raw responses for a future review screen. It is not displayed in the MVP; the result screen uses score, max_score and duration_ms. 

{
  "question-uuid-1": 2,
  "question-uuid-2": [0, 3],
  "question-uuid-3": 12.5,
  "question-uuid-4": null
}
Deletion is permanent. There is no editing or restore in the MVP, so every cascade delete is confirmed with counts before it runs. The confirmation names the sub-folders, quizzes and attempts that will be removed.
